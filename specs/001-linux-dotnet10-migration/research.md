# Research: MonoDevelop on Linux with .NET 10 LTS and GTK3

Phase 0 research for the plan. Every decision lists rationale, alternatives and the evidence
that backs it. Evidence files live in `docs/evidence/M0/`.

## Baseline facts (static inventory)

Source: `docs/evidence/M0/inventory.md` (generated by `scripts/inventory.sh`).

- 99 non-fixture csproj (4 SDK-style, 95 on `$(MDFrameworkVersion)` = v4.7.2); 218 entries in
  `Main.sln`; 5,338 C# files; 70 `*.addin.xml` manifests.
- GTK stack referenced in 1,167 files; GTK2-only APIs: `ExposeEvent` 90, `SizeRequested` 67,
  `Gdk.GC/Drawable` 45, `Gtk.Rc` 9; Stetic-generated code 187 files; Xwt 393 files.
- Mono.Unix/Mono.Posix 229 files (mostly `Catalog.GetString` in generated code); Remoting 39–43
  files; BinaryFormatter 11; `Thread.Abort` 5; delegate `BeginInvoke` 2; `Assembly.LoadFrom` & co 18;
  CodeDom 112; System.Web 58; 700 `[DllImport]` lines; 7 `.dll.config` dllmap files.
- Tests: 3,086 `[Test]` + 709 `[TestCase]`, 110 `[Ignore]`; largest suites: Core.Tests 853,
  PackageManagement 729, Ide.Tests 710, DotNetCore 411, CSharpBinding 410, TextEditor 319, Xml 286.
- Central versions: Roslyn 3.4.0-beta4, VS editor 16.1.28, Newtonsoft 12.0.2, NuGet 5.4.0,
  Cecil 0.10.1, NUnit 2.7.0 / 3.9.0 (see inventory for the full list).
- Submodules: all 15 initialized inside the container; SHAs recorded in the inventory.

## Decisions

### D1 — Solution strategy (ADR 0002)
- **Decision**: new classic `main/MonoDevelop.Linux.sln` growing per wave; it replaces `Main.sln`
  when M5 completes.
- **Rationale**: the IDE's own `SlnFile` parser cannot read `.slnx`, and a separate solution lets the
  Linux build be green from day one while legacy projects remain untouched.
- **Alternatives**: `.slnx` (IDE can't open itself); solution filter `.slnf` over `Main.sln` (still
  loads 218 entries, many unbuildable); editing `Main.sln` in place (no green baseline).

### D2 — Project conversion (ADR 0003)
- **Decision**: in-place conversion to SDK-style `net10.0`, `EnableDefaultCompileItems=false` until a
  project is green; new props in `main/msbuild/Linux/`; `BuildVariables.cs` generated by an MSBuild
  target from `version.config`.
- **Rationale**: smallest diff per project; keeps history (`git log --follow`) and allows
  per-project reverts.
- **Alternatives**: new parallel csproj files (double maintenance); keeping legacy build alive
  (impossible — no Mono, dead feeds, private repo).

### D3 — Packages and feeds (ADR 0004)
- **Decision**: CPM (`main/Directory.Packages.props`), nuget.org-only `NuGet.config`; the dnceng
  `dotnet-tools` feed is allowed only for Roslyn EditorFeatures if/when W4 needs it (MIT); lock files;
  `NuGetAudit` on.
- **Rationale**: the old feeds (myget, appveyor, dotnetfeed) are dead; CPM makes upgrades atomic.

### D4 — Third-party code (ADR 0005)
- **Decision**: maintained NuGet package when available (Mono.Addins 1.4.1, LibGit2Sharp 0.32,
  Mono.Cecil 0.11.6, GtkSharp 3.24.24); otherwise vendor into `main/vendor/<name>/` with
  `UPSTREAM.md`: xwt (NuGet Xwt is net472-only), Mono.Addins.Gui (GTK3 port), Mono.Debugging from
  debugger-libs, a vs-editor-api text subset, GuiUnit replaced by NUnit. Submodules are removed from
  `.gitmodules` as their replacement lands.
- **Rationale**: maintainer decision (same repository, no external forks); vendoring makes patches
  reviewable and builds reproducible.

### D5 — Add-in system on CoreCLR (ADR 0006)
- **Decision**: Mono.Addins 1.4.1 from NuGet, single default `AssemblyLoadContext`, in-process
  registry update; registry directory isolated per test run.
- **Rationale**: T007 proved the model; MEF/Roslyn require single type identity (no per-add-in ALC).
- **Alternatives**: per-add-in `AssemblyLoadContext` (breaks shared types); rewriting the add-in
  system (out of scope).

### D6 — Target runtime (ADR 0007)
- **Decision**: add `DotNetCoreTargetRuntime` + factory (MSBuild from the SDK located by
  Microsoft.Build.Locator; no GAC; reference packs from the SDK); guard `SystemAssemblyService`
  against a null current runtime.
- **Rationale**: without Mono, `MonoRuntimeInfo.FromCurrentRuntime` returns null and
  `MsNetTargetRuntimeFactory` is Windows-only → NRE at start-up.

### D7 — MSBuild hosting (ADR 0008)
- **Decision**: `MSBuildLocator.RegisterInstance` first thing in `mdtool`/Startup/builder `Main`;
  keep MonoDevelop's own evaluator in-process for now; builds run in the out-of-process builder
  retargeted to `net10.0` (existing TCP + `BinaryMessage` protocol), launched with `dotnet exec`;
  `Thread.Abort` → `BuildManager.CancelAllSubmissions`.
- **Alternatives**: in-process builds (MSBuild node reuse and assembly conflicts inside the IDE);
  switching evaluation to `ProjectInstance` now (larger change; backlog B35).

### D8 — Remoting and serialization (ADR 0009)
- **Decision**: delete Remoting-based infrastructure (`RemotingService`, `ProcessHostController`,
  `RemoteProcessObject`, sinks); `CallContext.LogicalSetData` → `AsyncLocal<T>`; InstrumentationService
  IPC over StreamJsonRpc 2.x; no BinaryFormatter anywhere.

### D9 — Roslyn (ADR 0010)
- **Decision**: Roslyn 5.9.0 pinned exactly; internal APIs through Krafs.Publicizer (T008).
- **Alternatives**: rewrite on public APIs only (months, blocks GUI); building a Roslyn fork with
  IVT (heavy, license-OK but unmaintainable).

### D10 — GTK3 port (ADR 0011)
- **Decision**: port per project/area without a compatibility shim; freeze Stetic-generated
  `Build()` code as normal source and delete `.stetic` files; GTK3 CSS for theming.
- **Rationale**: `ExposeEvent`→`Drawn`, size negotiation and styles changed semantically; a shim
  would hide bugs. Stetic is GTK2-only and cannot regenerate code.

### D11 — Editor (ADR 0012)
- **Decision**: keep Mono.TextEditor + SourceEditor2 over a vendored vs-editor-api text subset.
- **Alternatives**: the newer Cocoa/WPF editor (not portable); AvalonEdit (WPF); GtkSourceView via
  GtkSharp (full rewrite of editor integrations).

### D12 — Native interop (ADR 0013)
- **Decision**: one `NativeLibraryMap` helper registering `NativeLibrary.SetDllImportResolver` per
  assembly with a table replacing the 7 `.dll.config` files (e.g. `libglib-2.0-0.dll` →
  `libglib-2.0.so.0`); `LibraryImport` source generation later for hot paths.

### D13 — Localization (ADR 0014)
- **Decision**: NGettext-based catalog behind the existing `GettextCatalog` API, loading the
  existing `.mo` files; no native libintl dependency.

### D14 — Tests (ADR 0015)
- **Decision**: NUnit 3.14 + Microsoft.NET.Test.Sdk + coverlet first (minimal churn:
  `TestFixtureSetUp` → `OneTimeSetUp` in 18 files, `ExpectedException` → `Assert.Throws`), UI-thread
  synchronization context via `[SetUpFixture]`; NUnit 4 later with NUnit.Analyzers fixes.

### D15 — Debugging user programs (ADR 0016)
- **Decision**: concrete `NetCoreDbgSession` deriving from the existing abstract
  `VSCodeDebuggerSession` (`GetDebugAdapterPath` → netcoredbg) using
  Microsoft.VisualStudio.Shared.VsCodeDebugProtocol 17.x; netcoredbg pinned by release + checksum.
- **Alternatives**: vsdbg (license forbids use outside Microsoft IDEs); Mono soft debugger (Mono only).
- **Implemented (T112, 2026-09-24)**: new add-in `MonoDevelop.Debugger.NetCoreDbg` (placement rationale in the
  ADR 0016 amendment). `NetCoreDbgEngine` and `NetCoreDbgSession` are based on `DotNetCoreDebuggerEngine.cs` and
  `DotNetCoreDebuggerSession.cs` of https://github.com/dotdevelop/monodevelop.netcoredbg (branch `dotdevelop`,
  `0a52b6c4c6de32a66d6549d3c6abca8152bf310d`, MIT), the add-in that https://github.com/dotdevelop/monodevelop
  `379883b7c5` adds as a submodule. Not taken: its GTK2 options panel, the lookup of a netcoredbg bundled under
  `AddIns/Samsung.Netcoredbg` and the `AspNetCoreExecutionCommand` reflection (the engine accepts any
  `dotnet <program>.dll` command). The session sends breakpoints before `configurationDone` (DAP order).

### D16 — Packaging (ADR 0017 companion, M7)
- **Decision**: Flatpak first on `org.gnome.Platform` with the .NET 10 SDK extension; self-contained
  publish inside; SDK access decision (host SDK via `flatpak-spawn --host` vs bundled SDK) taken in
  M7 ADR; older dependencies may be bundled.

### D17 — Execution environment (constitution I)
- **Decision**: all commands via `./scripts/pm` (rootless podman, `--userns=keep-id`, main repository
  mounted at its host path so worktree `.git` indirection works, `md-home` volume for caches).
- **Evidence**: T001 — image `localhost/md-dev:<hash>` with SDK 10.0.401, no Mono;
  `git status` works inside the container.
