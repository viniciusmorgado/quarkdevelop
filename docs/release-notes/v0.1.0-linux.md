# MonoDevelop 0.1.0-linux

This is the first release of MonoDevelop on Linux, .NET 10 LTS and GTK 3. It is a pre-release.

MonoDevelop 8.6 ran on Mono and .NET Framework 4.7.2 with a GTK 2 interface, and its build no longer worked:
the package feeds were dead, it depended on Mono, and it used private repositories. This release runs on
.NET 10 (CoreCLR) and GTK 3, on X11 and Wayland. It is built and tested entirely in a container that anyone can
reproduce. Windows and macOS are not supported.

## What works

- **Start-up.** The IDE starts in about 2 seconds to its main window on a cold profile, on X11 and on Wayland.
- **Projects.** It opens, edits and builds SDK-style C# solutions (`.sln`) with the installed .NET SDK. Build
  errors are listed in the Errors pad, and double-clicking one jumps to the file and line.
- **C# editing.** Roslyn 5.9 drives the editor:
  - highlighting of C# 8–14 (records, raw strings, collection expressions, `field`, `extension`, and so on);
  - completion, refactorings and go to definition;
  - SDK-generated sources, including global usings for `ImplicitUsings` projects;
  - source generators (`[GeneratedRegex]`, `[LibraryImport]`, System.Text.Json). Go to definition opens the
    generated code read-only.
- **New projects and files.** New Project and New File list the templates of the installed SDK, the same ones
  `dotnet new list` shows. They are grouped by category (Common, Web, Test, Config, MSBuild, Solution), C# and F#
  only, and Linux-capable templates only. The IDE creates projects and files by calling `dotnet new`.
- **Debugging.** .NET 10 programs are debugged with netcoredbg: breakpoints, stepping, locals, watch, exceptions and
  exit codes. The IDE itself can be debugged from VS Code/VSCodium (`.vscode/launch.json`) or with
  `scripts/debug.sh`.
- **Unit tests.** NUnit, xUnit and MSTest projects run through the VSTest platform.
- **NuGet.** Package references can be added, updated, removed and restored (NuGet 7.9, loaded from the .NET SDK;
  requires SDK 10.0.4xx or newer).
- **Git.** Status, diff, blame and history work through LibGit2Sharp.
- **Other add-ins.** The assembly browser, hex editor, regex toolkit, DocFood, Gettext and XML editor are
  available.
- **Command line.** `mdtool build` builds and cleans SDK-style projects and solutions.
- **Logs.** Logs are structured, with the level set by `MD_LOG_LEVEL` and `MD_LOG_FORMAT=json` for JSON output.
  Metrics and traces go through `System.Diagnostics.Metrics`/`ActivitySource` (meter and source `MonoDevelop`).

## Install

- **Flatpak (recommended):** the `monodevelop.flatpak` bundle attached to the release (app id
  `io.github.viniciusmorgado.MonoDevelop`, runtime `org.gnome.Platform` 51). It carries its own .NET 10 SDK
  (10.0.401).

  ```bash
  flatpak install --user monodevelop.flatpak
  flatpak run io.github.viniciusmorgado.MonoDevelop
  ```

- **From source:** only podman and git are needed on the host. See [docs/linux/setup.md](../linux/setup.md).

  ```bash
  ./scripts/pm ./scripts/setup.sh && ./scripts/pm ./scripts/build.sh && ./scripts/pm ./scripts/run.sh
  ```

## Quality

The full `scripts/ci.sh` gate passes in under 10 minutes of the 15-minute budget. It covers:
- lint;
- the Release build with warnings as errors (per-project legacy baselines, shrunk by 23% in this release);
- 12 test suites with about 3,900 tests, run in two parallel lanes;
- a vulnerability audit (0 findings);
- an mdtool smoke test;
- five GUI smoke tests under Xvfb or Weston:
  - build a solution;
  - navigate from the Errors pad;
  - modern C# with source generators;
  - debug to a breakpoint;
  - Wayland.

The coverage ratchet is `MonoDevelop.Core` 66.5%, `MonoDevelop.Ide` 21.0% and 29.0% overall. It cannot decrease.

The acceptance checklist is in [docs/evidence/M9/acceptance.md](../evidence/M9/acceptance.md).

## Breaking changes

The complete list is in [docs/BREAKING-CHANGES.md](../BREAKING-CHANGES.md). The main points:
- **Platforms:** Linux only. Windows and macOS builds, installers and platform add-ins are gone.
- **Toolchain:**
  - no Mono;
  - no GTK 2 themes (`gtkrc`); GTK 3 themes, including dark variants, apply;
  - no autotools, `configure` or `Main.sln` (the solution is `main/MonoDevelop.Linux.sln`);
  - no git submodules.
- **Removed features:** ASP.NET WebForms/MVC 5, Web References (WCF), the Stetic GTK# designer, Subversion, the Mono
  and GDB debuggers, VB.NET, the IL assembler, and the built-in project and file templates. The templates are now
  those of the SDK.
- **Deferred features:** an F# language binding (F# projects can be created and built, but have no editor
  support yet), ASP.NET Core project tooling, Deployment/Packaging add-ins and T4 text templating.

## Known issues

- F# projects load as unsupported projects in the IDE (T154).
- Source generators from project references (`OutputItemType="Analyzer"`) are not loaded yet. Generated files do not
  show under the Dependencies node (T149).
- The New Project dialog offers only the language choice for each template. Other template options use their
  defaults.
- Some widgets still use thin GTK 2-to-GTK 3 port helpers (T150). They have no visible effect.
- The Flatpak has been tested in a clean container installation, not yet on a real desktop session.
