# 0003 — In-place SDK-style conversion to net10.0

- Status: Accepted
- Date: 2026-09-23

## Context and Problem Statement

95 of 99 projects are legacy csproj files targeting `v4.7.2` through a props chain
(`MonoDevelop.props`, `msbuild/MonoDevelop.{Before,After}Common.*`, `ReferencesGtk.props`,
`ReferencesVSEditor.*.props`) that depends on Mono's GAC, private repos and dead feeds.

## Considered Options

1. Convert each csproj in place to SDK-style `net10.0`.
2. Create new parallel csproj files next to the old ones.
3. Keep legacy build working in parallel.

## Decision Outcome

Option 1, with:

- `EnableDefaultCompileItems=false` (explicit `Compile` lists) until a project is green — source
  folders contain files that must not compile on Linux; switch to globs per project later.
- New shared props in `main/msbuild/Linux/{Common,Addin,Test}.props`; `Directory.Build.props`
  branches on `$(UsingMicrosoftNETSdk)` so converted projects never import the legacy chain.
- Output layout kept: `main/build/bin` (core) and `main/build/AddIns/<dir>` (add-ins),
  `AppendTargetFrameworkToOutputPath=false`.
- `BuildVariables.cs` generated by an MSBuild target from `version.config` (no `configure.exe`); since 2026-09-25 from
  the product version in `main/Directory.Build.props` (ADR 0021).
- Public signing with `msbuild/MonoDevelop-Public.snk` kept (assembly identity continuity).
- Language version: `latest` (C# 14 with SDK 10). Verified that the legacy core compiles unchanged
  (no new errors or warning IDs); needed for module initializers (ADR 0013).
- `GenerateAssemblyInfo=true` with every legacy attribute generator disabled, because the SDK only
  emits `InternalsVisibleTo` items when assembly-info generation is on.
- Output layout is assigned in `OutputLayout.targets`, imported through `BeforeMicrosoftNETSdkTargets`
  (after the project body, before the SDK derives `OutDir`).

Option 3 is impossible (no Mono, dead feeds, private `md-addins`). Reversibility comes from one
wave/project per commit.

### Consequences

- Good: minimal diffs, `git log --follow` history preserved, per-project revert.
- Bad: long explicit `Compile` lists remain for a while.
