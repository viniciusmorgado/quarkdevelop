# 0024 — Toplevels and GDK windows created from C# kept alive by the IDE (GtkSharp toggle-reference workaround)

- Status: Accepted
- Date: 2026-09-24

## Context and Problem Statement

Under Xvfb, `MonoDevelop.Ide.Gtk3.Tests` crashed its test host intermittently (about 3 in 8 runs, "Test host process
crashed" inside `SourceEditorTests`) or later tests found unrealized widgets. Any toplevel created from C#
(`new Gtk.Window (...)`, `new Gtk.OffscreenWindow ()`, `new Gtk.Dialog ()`, managed subclasses) and `Destroy ()`ed made
GObject log `g_object_remove_toggle_ref: assertion 'G_IS_OBJECT (object)' failed` once its wrapper was disposed or
collected (a GC in a later test was enough).

Cause, in GtkSharp 3.24.24.95 (`GLibSharp`, identical to upstream `develop`; the package has no source tag):

- `gtk_window_init` (and `gtk_invisible_init`) sinks the floating reference of a new instance and keeps it for GTK
  (`has_user_ref_count`); the GTK destroy handler drops it. `gtk_window_new` returns a reference the caller does not own.
- `GLib.Object.Raw` assumes that a constructor returned a reference for the wrapper: `ToggleRef` adds the toggle
  reference and unrefs the reference it believes it owns, which is GTK's. The toplevel's ref count is 1 and consists of
  the wrapper's toggle reference only. `Gtk.Widget.Dispose` even documents that "we do not hold a ref, only a toggle ref"
  for toplevels and compensates when the wrapper is disposed first.
- `gtk_widget_destroy` therefore frees the instance while GtkSharp still maps it to its wrapper. Disposing or collecting
  the wrapper later removes the toggle reference from freed memory (assertion, or a crash once the memory is reused);
  `Destroy ()` itself also disconnects a signal handler from the freed instance. Wrappers made by
  `GLib.Object.GetObject` take a reference of their own and are not affected; non-toplevel widgets are sunk properly.
- The same happens to a `GdkWindow` created from C#: `gdk_window_destroy` drops the reference returned by
  `gdk_window_new`, which the wrapper has taken over. Custom widgets create their window in `OnRealized`
  (`GdkWindow = new Gdk.Window (...)`, e.g. `Mono.TextEditor.TextArea`) and GTK destroys it when the widget is
  unrealized. This was the test-host crash (SIGSEGV in `g_object_remove_toggle_ref` from
  `ToggleRef.PerformQueuedUnrefs`, crash report of `TextEditorOverviewTests` after `SourceEditorTests`).

The IDE, its add-ins and the vendored Xwt create toplevels in about 185 places, so fixing call sites is not an option.

## Decision Drivers

- One fix for every toplevel created from C#, including add-ins and Xwt; no behavior change for correct code.
- C# first; no fork of the binding unless necessary (GtkSharp's sources are generated by `GapiCodegen` at build time).
- Keep the NuGet `GtkSharp` 3.24.24.95 (ADR 0011) and its assembly identity.

## Considered Options

1. **Runtime workaround in `MonoDevelop.Ide`** (`MonoDevelop.Components.GtkToplevelReferences`), installed right after
   `Gtk.Application.Init`.
2. Vendor GtkSharp in `main/vendor/` (generator, API XML, all binding assemblies) and take a GTK reference for toplevels
   in the constructors: the proper fix, but a large vendored tree and a replacement of every GtkSharp package.
3. Rewrite `GtkSharp.dll` at build time (Mono.Cecil): patches a signed binary, and every consumer must pick the
   rewritten copy.
4. Detour GtkSharp methods at run time (Harmony/MonoMod): new dependency, fragile on new runtimes.

## Decision Outcome

Option 1. `GtkToplevelReferences.Install ()` replaces the `constructed` virtual function in the class structures of
`GtkWindow`, `GtkInvisible` and `GdkWindow` (and of their already initialized subclasses that inherited it; classes
initialized later copy the hooked pointer). The hook chains to the original and adds a GObject weak reference to every instance.
Weak notifications run at the end of each dispose (`g_object_run_dispose` in `gtk_widget_destroy`, and the last one
before finalization), which holds exactly one reference:

- no wrapper registered (`GLib.Object.TryGetObject`): nothing to do (GtkSharp unregisters a wrapper before it drops its
  toggle reference, and natively created windows have none);
- ref count greater than 1: the instance survives this dispose; the weak reference is added again for the next one
  (dialogs destroyed in their own `Response` handler: the emission holds a reference);
- ref count 1 with a wrapper registered: the wrapper's toggle reference was never counted and GTK has just dropped the
  reference it had taken over. The notification adds it back (resurrection in dispose is supported by GObject, which
  then sends the toggle notification) and marks the `Gtk.Widget` as destroyed (private field `destroyed`, so that
  `Dispose ()` does not take another reference for a second `gtk_widget_destroy`).

The destroyed instance then lives until the wrapper is disposed or collected, as it would if GtkSharp had counted its
toggle reference.

`MD_GTK_REFERENCE_DIAGNOSTICS=1` hooks `GObject` itself instead (every type) and logs a warning for each repaired
reference. Over the whole `MonoDevelop.Ide.Gtk3.Tests` suite it repaired only `GtkWindow` (and subclasses),
`GtkInvisible` and `GdkWindow` instances, hence the list; hooking every type by default would add a weak reference and
two managed transitions to every GObject (CSS nodes, styles, ...). Installed by `IdeTheme.InitializeGtk`, `SetupApp` and the test set-ups that initialize GTK
(`GtkFixture`, UnitTesting, PackageManagement, Git).

### Consequences

- Good: fixes the assertions/crashes after `Destroy ()` for every toplevel created from C#; freed instances are no
  longer left in GtkSharp's handle map, where a new object at the same address could get the stale wrapper.
- Good: covered by `ToplevelReferenceTests` (Xvfb): destroyed toplevels (Window, popup, OffscreenWindow, Dialog,
  managed subclass, GtkInvisible) and the GdkWindow of an unrealized custom widget live until their wrapper is
  disposed or collected, then are freed; undestroyed, natively destroyed, natively created and unwrapped windows are
  freed; no GObject critical is logged.
- Bad: depends on the GObject class layout (`constructed` is the tenth pointer of `GObjectClass`, public ABI), on
  `ref_count` following the `GTypeInstance` pointer (public ABI), and on GtkSharp internals (`TryGetObject` semantics,
  the private `Gtk.Widget.destroyed` field; without it natively destroyed toplevels that are disposed later leak).
  The tests fail if a GtkSharp update changes this.
- Bad: instances constructed before `Install ()` are not covered, and neither are other types that own the reference
  their constructor returns (none found; see the diagnostics switch).
- Neutral: to be removed when GtkSharp counts the reference itself (upstream issue to be filed; the package is
  unmaintained since 2024).
